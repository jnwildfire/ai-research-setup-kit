Guide 01

Three roots, never mixed

Three top folders, one kind of thing each. Code in git on your own disk, where every change is kept. Data and the other files of the work (figures, slides, documents, transcripts) on the institution's backed-up drive. Knowledge in a notes vault that you and the agent both write.

Data moves one way: raw as received, processed by code, outputs made by a script. So every number traces back to its delivery.

Never search the drive from the top. A cloud drive downloads every file a search touches.

Guide 02

The agent and its desk

Before you type a word, the desk already holds the agent's own instructions, your rules file, one line per skill, the tools of each connector you switched on (a connector, or Model Context Protocol (MCP) server, gives the agent tools for a service), and its memory index.

The session piles on top. The whole desk is read again on every turn; when it is full, a summary is kept and the rest forgotten.

  • You lay the desk, by what you write and what you switch on.
  • A crowded desk is read less carefully, and paid for on every turn.
  • A new task is a new session. Files hold what must be remembered.

In the author's setup, 60,000 to 66,000 tokens lie on the desk before the first word (73 sessions, October 2026). /context shows yours.

Guides 02, 03 and 04

Four kinds of instruction, and when each loads

When a kind loads decides what belongs in it.

Rules

Always, read whole

Only what nothing else would prompt the agent to look up, each line with its reason. Under 200 lines.

Skills

On trigger

A procedure in its own folder. One line on the desk; the rest loads when a request matches, or on /name.

Hooks

Always, whatever the agent decides

A script the program runs before each action. Never read, so never forgotten: deny, ask or pass.

Memory

Written by the agent

Its own notes on where things stand. One screen each, and never the place for a rule.

Guide 08

The knowledge base, in lanes

A lane is a kind of note with its own job and its own author. The names are yours; the author's vault started from Research Memex.

Two lanes are gates: the inbox and the raw input hold unvetted capture, never cited until it is processed into a proper note.

The agent writes into a lane of its own: plans, analyses, decisions, long answers, each a dated note. After thirty days without an edit, a note moves to its month's archive, and links still find it.

Guides 05 and 07

Literature: the paper itself

One citation key, generated once and never changed, joins the reference manager item, its literature card, every link in the notes and the citation in the manuscript.

A literature card indexes what a paper holds for your work, each item with its page and a short quotation, and says what was read: the full text, some sections, or the abstract.

When a claim carries weight, the agent opens the paper itself and quotes the passage with its page. A citation no search finds is not used.

In the author's setup: Zotero, Better BibTeX, ZotLit, a full-text connector, MinerU for pivotal papers, scite and Scopus for the checks. Any tools with stable keys will do.

Guide 05

Products, and the referee pass before anything leaves

Each product is saved in its root: a note in the vault, a figure in the data root, code in git, a paper in a repository or on the drive.

Before anything leaves, a referee pass: a new agent that did not write the text, on the strongest model at the highest effort, checks every claim against its source. You decide, and answer the review in a table.

Every number that carries weight says what kind of number it is. 80 kWh/m² can be measured, simulated, a design value or a model input; only the basis word tells which.

Guide 05

Decisions as issues

For a design that unfolds over weeks, each open decision gets its own ticket in a tracker such as GitHub, linked from one map issue and from the tickets it blocks.

The discussion stays on the ticket. Closing it records what was decided, when and why, so the reason is still there when someone asks.

For a meeting, a decisions table at the top of the note does the same job. A blank verdict cell means approved.

Guides 05 and 06

One base, several people

An assistant writes into the same vault, a student learns from its concept notes, a partner uses a tool built from the data.

Each note has one owner; others comment or propose. In folders shared in real time, the agent changes one passage at a time, never a whole note.

Data about people or from partners: the data agreement decides first. The agent works on it through scripts that report aggregates, and none of it goes into a public repository.

Guide 04

The night shift

A job that runs while you are away cannot ask, so the questions come first. Its plan names every folder it will write to; you say yes once, and the session writes a grant with an expiry. The guard refuses everything else.

Keep-awake holds the laptop awake with the lid closed. On battery at 20 %, the guard pauses the job.

The job commits on its own branch, never merges, and writes down what it could not ask. The morning report takes two minutes.

What never runs unattended is your own list. The starter kit's is a simulation, an account, an install, a rule; this kit adds a payment.

Guide 05

Which model for which work

Route by the kind of work first, then by effort. Raise the effort before you change the model.

  • Scientific work (synthesis across papers, method design, results against the literature): the research lane, Fable 5.1 at the highest effort.
  • Visual work (user interfaces, images and video, and any judgement on something rendered): Opus 5.5, even when the task looks small or sits inside a research task.
  • Everything else: Opus 5.5 at high effort, and at the highest effort when it is hard.

No Sonnet or Haiku lane, by design. Quality comes first here, and a cheap pass that needs a redo is not cheap.

How to start

  1. Have the first track in place: Claude Code installed and signed in, as in the AI research starter kit, and Python 3.8 or later.
  2. Read both guides 06, the starter kit's and this kit's. They decide what the agent may read.
  3. Download the kit from GitHub into a folder outside your cloud drive.
  4. Open that folder in Claude Code and say: Read START-HERE.md and set me up.
  5. In the first week, read guides 02 and 05. Read guide 04 before the first job that runs while you are away.

The set-up ends with a refusal. The agent creates a test file among the originals and tries to change it; the guard must refuse in front of you. A guard that never refused anything may not be running.

About an hour, in two sessions. The agent asks where your code, data and notes are, lays your rules file, installs the skills and the guard, and changes nothing of yours without asking.
